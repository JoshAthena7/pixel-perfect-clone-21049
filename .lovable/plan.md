
# Auto-populate Mission Setup Record from IRIS

Goal: when an admin opens the Setup Record for a freshly-activated mission, every field IRIS can infer is already filled with an ⚡ "IRIS suggested" marker. Manual entries are never overwritten. The admin can bulk-approve or review field-by-field.

## Scope

Frontend + one server function. No schema migration for the user-visible setup fields themselves — they already exist on `missions` and related tables. One new column on `missions` to track the auto-fill state per mission.

## 1. Data model (one migration)

Add to `public.missions`:
- `iris_setup_autofill_status text` — `null` | `"pending"` | `"suggested"` | `"approved"` | `"reviewing"`
- `iris_setup_autofill_at timestamptz`
- `iris_setup_suggested_fields jsonb` — `{ field_key: { value, source, generated_at } }` map of every field IRIS pre-filled. Used to (a) render ⚡ markers, (b) detect that a saved value still matches the suggestion (so the marker stays) vs. has been edited (so it goes away).

Mission RLS policies for `missions` already cover updates by mission members / admins. No new GRANTs needed.

## 2. New server function: `irisPopulateSetupRecord`

File: `src/lib/iris-setup-autofill.functions.ts` (client-safe path).

`createServerFn({ method: "POST" })` + `requireSupabaseAuth`, input `{ missionId, force?: boolean }`.

Behavior:
1. Load mission row + linked sources in parallel:
   - `mission_vault_documents` + `document_extractions` (RFP + uploaded knowledge docs)
   - `briefing_book_sections` (already generated by `regenerateBriefingBook`)
   - `mission_intelligence` rows written by the kickoff pipeline (signals, risks, client_intel, win_themes, strategy)
   - Strategic Foundation fields already on the mission row
   - `win_themes`, `mission_evaluation_criteria`, `mission_client_intel`
2. If `iris_setup_autofill_status` is already `"suggested"` / `"approved"` and `force !== true`, return existing `iris_setup_suggested_fields` without re-calling AI (idempotent first-open behavior).
3. Build a single prompt to `google/gemini-2.5-pro` via the Lovable AI gateway (wrapped in `withAICircuit`). Structured JSON output via `response_format: json_object` and an explicit schema in the system message. One call, not one per field — cheaper, more coherent.
4. Schema returned by the model (keys = setup form fields):
   ```
   {
     description, client_name, agency_name, submission_deadline,
     contract_value, contract_term, mission_highlights, client_strengths,
     win_strategy, program_goals, key_contract_requirements (array),
     incumbent_name, evaluation_criteria (array of {name, weight, notes}),
     geographic_scope, population_served, win_themes (array)
   }
   ```
   Each value is either a string/array or `null` when not inferable.
5. Merge results into `missions` and child tables ONLY for fields that are currently empty/null. Never overwrite admin entries.
6. Write the full suggestion map to `iris_setup_suggested_fields` and set `iris_setup_autofill_status = "suggested"`, `iris_setup_autofill_at = now()`.
7. Return `{ status, suggestedFields, written: number, skipped: number }`.

Errors are caught per-section; partial success is fine. AI circuit-breaker open → return early with `status: "pending"`.

## 3. Trigger point

Auto-population runs once on **first open of the Setup Record after activation**, not at activation time. Reasons:
- Activation already runs the briefing-book regen + kickoff pipeline; auto-fill needs those outputs to exist.
- Lazy trigger avoids charging gateway tokens for missions whose admin never opens the Setup Record.

In `src/routes/_authenticated/admin/missions.$missionId.setup.tsx`:
- On mount, if `mission.iris_setup_autofill_status` is `null` AND `mission.iris_kickoff_status === "complete"`, fire `irisPopulateSetupRecord({ missionId })` via `useMutation`, then `router.invalidate()`.
- If kickoff is still running, show a small "IRIS is still preparing suggestions…" hint instead of auto-firing.

## 4. UI changes in the Setup Record form

### Banner (top of the form, only when `status === "suggested"`)

```
⚡ IRIS pre-filled this record from your uploaded documents.
   Review each field — suggested values are marked ⚡.
   [ Looks good — approve all ]   [ I'll review manually ]
```

- **Approve all** → server fn `approveIrisSetupSuggestions({ missionId })` sets `iris_setup_autofill_status = "approved"`, banner disappears, ⚡ markers go away on next render.
- **I'll review manually** → `iris_setup_autofill_status = "reviewing"`, banner disappears, ⚡ markers stay.

### Per-field ⚡ marker

Small `IrisSuggestedBadge` component rendered next to the field label whenever:
- `iris_setup_suggested_fields[field_key]` exists, AND
- The current saved value still equals the suggested value, AND
- `iris_setup_autofill_status !== "approved"`.

Once the admin edits the field, the local value diverges from the suggestion and the badge disappears on next save. Tooltip on the badge: "IRIS suggested this from <source>. Edit to override."

### Fields IRIS cannot fill

For `internal_notes`, `red_team_flags`, `executive_sponsor_notes`, custom fields — leave blank, render a muted placeholder `"IRIS can't infer this — add your own context"`. No ⚡ badge.

## Technical details

- Single AI call per mission via `withAICircuit` keeps gateway cost predictable (~one Gemini 2.5 Pro request, ~6–10k input tokens given full RFP excerpts + briefing book).
- Field-level "is this still a suggestion?" check uses deep equality on string and array fields. For long text fields, normalize whitespace before comparing.
- Idempotency: `force=false` short-circuits if `iris_setup_suggested_fields` already populated, so re-opening the page doesn't re-charge the gateway.
- Auto-fill state is per-mission, never overwritten by the admin's edits.
- No changes to the activation wizard, `regenerateBriefingBook`, or the kickoff pipeline.
- No changes to RLS: writes happen through `requireSupabaseAuth`-scoped client, respecting existing mission policies.

## Out of scope (will not do in this pass)

- Per-field "regenerate this suggestion" buttons.
- Re-running auto-fill when new documents are uploaded post-activation (admin can hit a manual "Refresh IRIS suggestions" button — happy to add later).
- Auto-population of Question records, Compliance Matrix, or sections — only the Setup Record fields listed in the spec.
