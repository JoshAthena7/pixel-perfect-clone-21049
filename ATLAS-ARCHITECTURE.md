## Overview

ATLAS is a mission-intelligence platform for Medicaid bid teams. Writers work
in the Flight Deck, captains run their teams from ATC, platform admins manage
intelligence and pipeline health in Olympus, and the IRIS briefing engine
grounds every question brief in ORACLE intelligence.

North Star: Truth → Intelligence → Understanding → Strategy → Execution.

## Design Principles

- One distinctive visual direction, not generic AI aesthetics. Dark surface
  `#070f1c`, gold accent `#d4af37`, semantic tokens in `src/styles.css`.
- All color/gradient/shadow values are semantic tokens — never hardcoded.
- Users only ever see the 5 IRIS Outputs (Mission Brief, Environmental
  Assessment, What the State Wants, Emerging Risks, Recommended Strategy).
- Intelligence graph first, UI second.

## Page Architecture

| Route | Owner | Purpose |
|---|---|---|
| `/` → `/missions` | All users | Mission switcher / portfolio |
| `/missions/$missionId/flight-deck` | Writers | Question-level brief, assist bar, sticky notes |
| `/missions/$missionId/war-room` | Captains | ATC: team pulse, mission radar, IRIS alerts, writer drawer (URL stays `war-room`; components are being renamed to ATC) |
| `/missions/$missionId/briefing` | All | Mission briefing room |
| `/missions/$missionId/intelligence` | All | ORACLE intelligence feed, Add Intel modal |
| `/olympus` | Admin only | ORACLE command surface: taxonomy browser, intel review queue, sources, pipeline health |
| `/admin/*` | Admin only | Team, settings, activity, insights, messaging |
| `/api/public/hooks/*` | Cron + webhooks | No-auth entry; verify caller in handler |

Role guard for `/olympus`: `useIsAdmin()` redirects non-admins to `/missions`.

## Database Schema

Source of truth: `src/integrations/supabase/types.ts` and `supabase/migrations/`.

Canonical tables (current):

- `oracle_signals` — intelligence nodes (formerly `oracle_nodes`)
- `oracle_taxonomy` — 67-node 9-domain taxonomy
- `oracle_source_registry` — 14 seeded sources
- `oracle_ingestion_queue` — raw scraped items pending classification
- `oracle_quality_measures`, `oracle_sdoh_data` — structured datasets
- `question_intel_links` — question ↔ oracle_signals map (formerly `oracle_question_intel`)
- `mission_team_members` — canonical mission membership (legacy `mission_members` still readable)
- `user_roles` + `has_role(_user_id, _role)` — canonical RBAC
- `profiles` — user profile; `is_platform_admin` column is **deprecated** (kept for
  back-compat; new code uses `has_role(auth.uid(), 'admin')`)

## ORACLE Architecture

Three source layers feed `oracle_signals`:

1. **Manual intake** — Add Intel modal in Intelligence page and Olympus.
2. **Automated pipeline** — three stages, each cron-triggered:
   - `runScraper()` — `/api/public/hooks/oracle-scraper` (every 4h)
   - `runClassifier()` — `/api/public/hooks/oracle-classifier` (every 30m)
   - `runPromoter()` — `/api/public/hooks/oracle-promoter` (every 30m)
   All defined in `src/lib/oracle/pipeline.server.ts`. Cron auth via
   `CRON_HOOK_SECRET`.
3. **Bulk seed** — `iris-bulk-feeds`, `iris-bulk-competitors`, `iris-seed-mission-intelligence`.

Five tagging dimensions: Mission Domain, Geography, Signal Type, Importance,
Time Horizon.

Nine domains live in `oracle_taxonomy`; see `docs/specs/oracle-taxonomy.md`.

## IRIS Briefing Architecture

`src/lib/iris-brief-generator.functions.ts` is the canonical Flight Deck
brief path. It runs four parallel `query_oracle` calls (decode, win-angle,
evidence, risk) before a single Lovable AI Gateway call, then upserts every
node used into `question_intel_links`. Six-layer output: decoded_intent,
evaluation_focus, recommended_approach, win_theme_connections, iris_evidence,
risk_flags.

The header of that file holds the full gateway call-site map; update it when
adding a new gateway caller.

## ATC Architecture

`src/components/war-room/WarRoomPage.tsx` (URL: `/war-room`, component
identity in transition to ATC). Panels: Team Pulse, Mission Radar, IRIS
Alerts, Writer Drawer. Heat borders driven by `useQuestionHealth`. Server
data in `src/lib/war-room.functions.ts`.

## Assist Bar

`src/components/flight-deck/FlightDeckAssistBar.tsx` — four buttons:
Check-In, Score Me, Sticky Notes, Mission Pulse. The legacy six-button
variant and the old Thread modal have been removed from the active flow
(Sticky Notes replaces Thread).

## Key Integrations

- **Lovable Cloud** — managed Supabase backend (auth, Postgres, storage).
- **Lovable AI Gateway** — `ai.gateway.lovable.dev`; key `LOVABLE_API_KEY`.
- **Slack / Teams** — `/api/public/hooks/*` webhooks for nudges and Pin to
  Slack. Currently stubbed (`console.log`) pending real webhook URLs in
  mission config — see Known Tech Debt.
- **pg_cron** — schedules scraper / classifier / promoter / daily monitors.

## Known Tech Debt

1. **War Room → ATC rename**: URL `/war-room` is intentionally preserved
   (per cleanup spec). Component / file identifiers still read `WarRoom`
   in ~20 files. Cosmetic; no behavioral impact. *Verify manually if a
   user-visible rename is desired.*
2. **`profiles.is_platform_admin`**: column still exists for back-compat;
   migrations reference it historically. Active code now reads
   `has_role(auth.uid(), 'admin')`. Drop after a full deploy + smoke test.
3. **Slack / Teams webhooks**: Nudge and Pin-to-Slack are `console.log`
   stubs in `NudgeModal.tsx` and `StickyNotesPanel.tsx`. Wire to real
   webhook URLs stored on the mission row before launch.
4. **Olympus review-drawer edit mode**: taxonomy override and relevance
   slider stubbed to a one-liner per Phase B confirmation.
5. **Console logs**: ORACLE pipeline informational logs are gated via
   `src/lib/debug-log.ts`. Error logs intentionally kept raw so they
   surface in production telemetry. Remaining IRIS/oracle `console.warn`
   sites are diagnostic; gate per-site if log volume becomes a problem.
